OS Systems — Updates

The Updating System for the whole Top Speed Service OS: every platform, the tech packs each platform runs and the version actually installed, and the 6-month update cycle that computes drift and turns it into a per-platform update plan. This console prepares, tracks and verifies updates — it never rewrites production code. Updates are applied through the normal build, push and owner-approval flow, then marked APPLIED and VERIFIED here.

Platforms — every OS surface in the registry, by division

Grouped by the corporate divisions: Top Speed OS (main), Top Speed Service OS (the service side) and Top Speed Sales OS (the retailing side). Drift is computed from the version actually recorded for each platform against the latest known version of the same pack. A platform marked UNKNOWN has versions that have not been read yet — the open cycle carries a verify task for it. No version is ever guessed.

Tech packs — latest known versions

Latest versions come from the npm registry when Refresh latest versions runs. A pack with no latest recorded yet shows “not checked” — its platforms read as UNKNOWN drift until the first refresh lands.
